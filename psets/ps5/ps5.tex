(Shortest Path without predecessor array)

Home Depot is providing a navigation service for delivery drivers who all leave from the same depot $s$. The road network is a directed, unweighted graph $G=(V,E)$, with \(n\) vertices and \(m\) edges, given by outgoing adjacency lists. Every road takes one unit of time to traverse. The graph and depot remain fixed throughout the day. Each query specifies a destination \(t\) and asks for a shortest path from \(s\) to \(t\), or \(\bot\) if none exists.

Unfortunately, the server that holds the predecessor array has crashed. The backup drive still has the graph, the distance array, and a log of every BFS frontier:
\[
F_i=\{v:\operatorname{dist}_G(s,v)=i\}.
\]
Each frontier is saved as a list of vertex names. Accessing the start of any frontier list takes constant time in the Word-RAM model.

The engineers deploy the following emergency query algorithm:

\begin{enumerate}
\item If \(\mathsf{dist}[t]=\infty\), return \(\bot\).
\item Otherwise, set \(d=\mathsf{dist}[t]\), start a path list containing \(t\), and set \(v=t\).
\item For \(i=d,d-1,\ldots,1\), scan the vertices \(u\) in \(F_{i-1}\) and their outgoing adjacency lists until finding an edge \((u,v)\). Append \(u\) to the path list and set \(v=u\).
\item Reverse the path list and return it.
\end{enumerate}

Every scan starts at the beginning of its list. In rush, the emergency algorithm has ended up answering queries independently: it does not save the predecessors it finds for later queries.

\begin{enumerate}
\item Prove that the emergency algorithm returns a shortest path whenever one exists. Explain why it always finds a suitable vertex in the preceding frontier and why accepting the first match cannot lead to a dead end.

\item Analyze the time to produce the backup during one BFS, and the worst-case time for one reachable-destination query in terms of \(n\) and \(m\). Account for the total work across all frontiers examined during a query. Can a query take \(\Omega(n)\) time even when the returned path has only two edges? Justify your answer with a graph and appropriate list orders.

\item Suppose \(q\) queries arrive, with reachable destinations at distances \(\ell_1,\ldots,\ell_q\). Compare the total running time, including initial preprocessing, of these approaches:

1. Run a fresh BFS for each query.

2. Preprocess once and use the emergency algorithm.

3. Preprocess once and use \(\mathsf{pred}\).

Give a family of graphs with \(m=\Theta(n)\) and \(q=\Theta(n)\) distinct destinations, all at distance two, for which the first two approaches take \(\Theta(n^2)\) total time, but the last takes \(\Theta(n)\). Specify the list orders used by the emergency algorithm.
\end{enumerate}

\item (Reductions Between Variants of \IndependentSet)
Consider the following three variants of the IndependentSet problem:
\begin{itemize}
    \item \IndependentSetOptimizationSearch: given a graph $G$, find the largest independent set in $G$.
    \item \IndependentSetThresholdSearch: given a graph $G$ and a number $k\in \N$, find an independent set of size at least $k$ in $G$ (if one exists).
    \item \IndependentSetThresholdDecision: given a graph $G$ and a number $k\in \N$, decide (by outputting YES or NO) whether or not there is an independent set of size at least $k$ in $G$.
\end{itemize}

\begin{enumerate}
\item Suppose that there is an algorithm running in time $T(n,m)\geq n+m$ that solves \IndependentSetOptimizationSearch\ on graphs with at most $n$ vertices and at most $m$ edges. In 8-10 sentences, describe an algorithm running in time $O(T(n,m))$ that solves \IndependentSetThresholdDecision. \emph{You \emph{do not} need to prove correctness nor analyze runtime for the algorithm you provide.}

\item Suppose that there is an algorithm running in time $T(n,m)\geq n+m$ that solves \IndependentSetThresholdSearch\ on graphs with at most $n$ vertices and at most $m$ edges. In 7-8 sentences, describe an algorithm running in time $O((\log n)\cdot T(n,m))$ that solves \IndependentSetOptimizationSearch.

\item Suppose that there is an algorithm
running in time $T(n,m)\geq n+m$ that solves \IndependentSetThresholdDecision. In 8-10 sentences, describe an algorithm running in time $O(n\cdot T(n,m))$ that solves \IndependentSetThresholdSearch.

\end{enumerate}
We remark (but you don't need to submit anything) that the combination of the three previous problem parts means that for every constant $c\in [1,2]$, if there is an algorithm solving any one of the three problems in time $(n+m)^{O(1)}\cdot c^n$, there are algorithms solving the other two problems in $(n+m)^{O(1)}\cdot c^n$ time. The best known algorithm (by Xiao and Nagamochi, 2013) has $c \approx 1.1996$.

\item (Maximal Independent Sets) \label{prob:maximalIS} Let $G=(V,E)$ be a graph. A set $S\subseteq V$ is a {\em maximal} independent set if we cannot add any vertices to $S$ while it remains an independent set. That is, for every vertex $v\in V\setminus S$, $S\cup\{v\}$ is not an independent set.

Given a graph $G$, a maximal independent set $S$ can be found in time $O(n+m)$ greedily. Specifically, we can start with an arbitrary node in $V$ and add it to S; iterate through each of that node's neighbors and remove them from $V$; and repeat with the next remaining element in the vertex set until all nodes are exhausted (you can take this fact as a given). Note that this is in sharp contrast to {\em maximum-size} independent sets, for which we do not know any subexponential-time algorithms.

We know that if $G$ is 3-colorable, then it has a 3-coloring $f$ in which the set of vertices of color 2 (i.e. $f^{-1}(2)$) is a maximal independent set (you can also take this fact as a given). It is also known that every graph $G$ has at most $3^{n/3}$ maximal independent sets, and there is an algorithm (the Bron--Kerbosch algorithm) that enumerates all of the maximal independent sets in time $O(3^{n/3}).$ Use these facts to show that a 3-coloring can be solved in time $O((n+m)\cdot 3^{n/3}) = O(1.45^n),$ improving the runtime of $O(1.89^n)$ from SRE2. \emph{Please keep your response within 10 sentences.}
