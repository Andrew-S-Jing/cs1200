\item (Shortest Path without predecessor array)

Home Depot is providing a navigation service for delivery drivers who all leave from the same depot $s$. The road network is a directed, unweighted graph $G=(V,E)$, with \(n\) vertices and \(m\) edges, given by outgoing adjacency lists. Every road takes one unit of time to traverse. The graph and depot remain fixed throughout the day. Each query specifies a destination \(t\) and asks for a shortest path from \(s\) to \(t\), or \(\bot\) if none exists.

Unfortunately, the server that holds the predecessor array has crashed. The backup drive still has the graph, the distance array, and a log of every frontier in the BFS starting from $s$:
\[
F_i=\{v:\operatorname{dist}_G(s,v)=i\}.
\]
Each frontier is saved as a list of vertex names. You may assume that accessing the start of any frontier list takes constant time in the Word-RAM model.

The engineers deploy the following emergency query algorithm that runs on the back-up drive data:

\begin{itemize}
\item If \(\mathsf{dist}[t]=\infty\), return \(\bot\).
\item Otherwise, set \(d=\mathsf{dist}[t]\), start a `path' array containing \(t\), and set \(v=t\).
\item For \(i=d,d-1,\ldots,1\), scan the vertices \(u\) in \(F_{i-1}\) and their outgoing adjacency lists until finding an edge \((u,v)\). Append \(u\) to the path list and set \(v=u\).
\item After the path array appends $s$, reverse the path array and return it.
\end{itemize}

Answer these questions:

\begin{enumerate}
\item Prove that the emergency algorithm returns a shortest path whenever one exists.

\begin{soln}
For the case where $dist[t]=\infty$, by definition there is no path from $s$ to $t$, meaning the $\bot$ result is correct.

For finite distances, we know there exists a path of length $dist[t]$. For each iteration in the loop, $dist[v]=i$, so $v\in F_i$, and since $F_i$ was constructed from $F_{i-1}$ we know there exists a $u$ with $dist[u]=i-1$ and an edge $(u,v)$. That means that every iteration of the loop does indeed append exactly one vertex to the path array, and that each new element has a distance 1 less than the last. Also, we know that the last appended element is definitely $s$ -- if $d=0$ then the loop is skipped and the path array only has $t$ (which equals $s$ in this case), and otherwise the last item is appended from $F_0$, which only contains $s$. Reversing the array doesn't change it's length, and the algorithm returns an array with $d+1$ elements, one vertex for each loop iteration plus $t$. After reversing, each consecutive pair in the array has an edge going from left to right, and the array starts at $s$ and ends with $t$. With $d+1$ elements, we know there is a length $d$ path from start to finish, and by definition this is a shortest path because $d=dist[t]$.
\end{soln}

\item Analyze the time to find the shortest path in the emergency algorithm, in terms of $n,m$. Can a finding a shortest path take $\Omega(n)$ time even when the returned path has only two edges? Justify your answer with a graph. Argue for or against the value of predecessor array (which is not accessible to the emergency algorithm above) in finding a shortest path.

\begin{soln}
Let's assume finding $dist[t]$. This means the first two steps in the algorithm are $O(1)$. The $d$ loop iterations each check $O(|F_{i-1}|)$ vertices for an edge with $v$ with $O(deg(u))$ time, along with a few constant-time things. As each vertex occurs in one frontier set and each edge occurs in one vertex's adjacency list, if $x$ is the number of vertices with distance $<dist[t]$, then the loop takes $O(x+\Sigma deg(x))$. In terms of $n$ and $m$ this is $O(n+m)$.

\includegraphics[width=0.7\textwidth]{graph.png}

This graph is an example of how a distance 2 vertex can still need to go through all the vertices in $F_1$ to find its predecessor, and since $s$ and $t$ also need to be visited, we've gone through $O(n)$ operations for this short path.

Predecessor arrays are a clear win for an application like this with one source vertex, dropping the needed runtime from $O(n+m)$ to $O(d)$ with an extra $O(n)$ space cost. We can simply traverse the predecessor chain backwards to make the array without exhaustively looking through the entire previous frontier. Unless space is a bottleneck, then this is beneficial.
\end{soln}
\end{enumerate}

\item  (Solving Games) 
     Consider playing a solo game on an $n\times n$ chessboard.  You have one piece, a chess knight, which starts in the lower-left corner, and your goal is to reach any of the other three corners in as few moves as possible.  Like a usual chess knight, in one move, you can move to any position that is two squares away in a horizontal direction and one square away in a vertical direction, or two squares away in a vertical direction and one square away in a horizontal direction.  There is a catch, however: some squares have visible landmines, so you cannot move to them (since you do not want set off an explosion). \


\begin{enumerate}
\item Give an algorithm that achieves the above goal in time $O(n^2)$ by reduction to either the ShortestWalks problem or the SingleSourceShortestPaths problem. The algorithm should output $\bot$ if no sequence of moves can take you to any of the other three corners when started in the lower-left corner. Discuss correctness and runtime of the algorithm. \emph{Please keep your response within 1 page.}(Note: if reducing to SingleSourceShortestPaths, we haven't defined abstractly what it means to reduce a computational problem to a data structure problem, but you may construct and use a SingleSourceShortestPaths data structure on an appropriately constructed graph.)

\begin{soln}
	
1. Construct a graph by defining $n^2$ vertices in the set $V$, one for each square.

2. For each non-landmine vertex

3. \quad Add an edge to the set $E$ for every valid move of the knight from that square (not to a landmine square).

4. For all 3 target corners

5. \quad $p=$ SingleSourceShortestPaths($(V, E), start, target$)

6. \quad If $p\neq\bot$ return $p$

7. return $\bot$

Since each square has at most 8 valid moves from it, we have $|E|=O(n^2)$. Then, we reduce to SingleSourceShortestPaths, returning $\bot$ if all three other corners' shortest paths are $\bot$ from the Oracle and the first returned path otherwise.

This algorithm is correct because the knight's position is equivalent to a state machine (graph) representing current position, and the only way to change states is to execute a valid move. Then, calculating a shortest path to a target state is solved by reducing to SingleSourceShortestPaths on (at most) all of the target states. The cost is that this reduction requires constructing the state machine (graph) by constructing $n^2$ vertices and $O(n^2)$ edges for a total $O(n^2)$ runtime and at most 3 Oracle calls (the $O(n)$ copies during the $p$ assignment are dominated by graph construction).
\end{soln}

\item (Maximal Independent Sets) \label{prob:maximalIS} Let $G=(V,E)$ be a graph. A set $S\subseteq V$ is a {\em maximal} independent set if we cannot add any vertices to $S$ while it remains an independent set. That is, for every vertex $v\in V\setminus S$, $S\cup\{v\}$ is not an independent set.

Given a graph $G$, a maximal independent set $S$ can be found in time $O(n+m)$ greedily. Specifically, we can start with an arbitrary node in $V$ and add it to S; iterate through each of that node's neighbors and remove them from $V$; and repeat with the next remaining element in the vertex set until all nodes are exhausted (you can take this fact as a given). Note that this is in sharp contrast to {\em maximum-size} independent sets, for which we do not know any subexponential-time algorithms.

We also know that if $G$ is 3-colorable, then it has a 3-coloring $f$ in which the set of vertices of color 2 (i.e. $f^{-1}(2)$) is a maximal independent set (you can also take this fact as a given). Further fact is that every graph $G$ has at most $3^{n/3}$ maximal independent sets, and there is an algorithm (the Bron--Kerbosch algorithm) that enumerates all of the maximal independent sets in time $O(3^{n/3}).$ Use these facts to show that a 3-coloring can be solved in time $O((n+m)\cdot 3^{n/3}) = O(1.45^n),$ improving the runtime of $O(1.89^n)$ from Lecture 12. \emph{Please keep your response within 10 sentences.}

\begin{soln}
	
1. $I=$ Bron-Kerbosch algorithm on $G$ ($|I|\leq 3^{n/3}$)

2. For $S\in I$

3. \quad $T=$ BFSColor($G\setminus S$)

4. \quad If $T\neq\bot$ return $T\cup S$, where $T$ is colors 0 and 1 and $S$ is color 2

5. return $\bot$

Here we use a version of BFSColor that returns $\bot$ the instant it assigns the color 3 (so it doubles as a 2-colorability detector). Since $G$ is 3-colorable $\implies f^{-1}(2)$ is maximally independent, in other words $G$ is 3-colorable $\implies\exists$ maximally independent $S$ with color 2 s.t. $G \setminus S$ is 2-colorable. So, we can check all maximally independent sets' complements for 2-colorablility (i.e. attempt a 3-coloring of $G$). If we exhaust all maximally independent sets without finding one, then the contrapositive of the earlier statement implies there is no 3-coloring of $G$. For each of the $O(3^{n/3})$ maximally independent subsets, generating $S$ and $G\setminus S$ takes a total of $O(n)$ time and checking for 2-colorability in $G\setminus S$ takes $O(n+m)$. So in total the loop takes $O((n+m)\cdot3^{n/3})$ time, and other factors like return construction are absorbed into that runtime.
\end{soln}
